## How codes appear

Every error message Vitrine shows ends with a code, for example "The user name or password is incorrect. (VIT-0101)".
The code is the same in every language, so support can identify a message whatever language the user interface uses.
The texts below are the English ones; `{0}`, `{1}` are filled in with details such as a file name or a Windows
message.

- The **audit log** records only the code of a failed attempt (`Detail` and `Data.code`), never the translated text.
- Scripts receive it in `%VITRINE_CODE%` (script `OnFailedAttempt`).
- The **local interface** answers in English with the code in the field `code`.

The list of codes is in [`src/Vitrine.Core/Localization/CoreText.cs`](../src/Vitrine.Core/Localization/CoreText.cs)
(class `ErrorCodes`); the texts are in `src/Vitrine.Core/Resources/CoreStrings*.resx` and
`src/Vitrine/Resources/UiStrings*.resx` under the key `Error_VITnnnn`. A unit test checks that every code appears on
this page.

## VIT-00xx – application and configuration

| Code | Message | Meaning | What to do |
|---|---|---|---|
| `VIT-0001` | {0} could not be read: {1} | A configuration file (`config.json`) cannot be read: not valid JSON, not a JSON object, too large, no access, or a value has the wrong type. A file that cannot be parsed is skipped; a value of the wrong type makes Vitrine use the **defaults for all settings, including those set by policy**, until the file is fixed. Shown in the settings overview under "Configuration has errors". | Fix the file named in the message (e.g. `"IdleMinutes": 5`, not `"five"`) and restart Vitrine or reload the policies. |
| `VIT-0002` | Policy {0} could not be read: {1} | A policy key in the registry could not be read completely; values after the error are not applied. | Check the values under the named key (type and content) – usually a value written by hand with the wrong type. |
| `VIT-0003` | Plugin {0} could not be loaded: {1} | A DLL in the `Plugins` folder could not be loaded or its types could not be read. | Check that the plugin targets .NET 10 and the current `Vitrine.Abstractions`; remove DLLs that do not belong there. |
| `VIT-0004` | Plugin {0}: the ID "{1}" is already in use. | Two plugins, or a plugin and a built-in method, use the same ID. The second one is not loaded. | Give the plugin a unique ID. |
| `VIT-0005` | {0} is already used by another program. | The lock shortcut cannot be registered because another program uses it. | Choose another shortcut under Settings › Lock, or close the other program. |
| `VIT-0006` | Saving failed: {0} | The settings could not be saved – also when the elevated save (`--apply-config`) failed; then `{0}` is `exit <code>` and the elevated process has shown its own message. | Check the message; check the permissions of `%ProgramData%\ICT-Baden\Vitrine` and `%ProgramData%\ICT-Baden`. |
| `VIT-0007` | Saving cancelled – administrator rights are required. | Saving needs administrator rights, and the Windows UAC prompt was cancelled. | Save again and confirm the UAC prompt with an administrator account. |
| `VIT-0008` | The configuration file is not valid: {0} | `Vitrine.exe --apply-config` (used internally when saving) got a file that is not a valid configuration. | Usually an internal error while saving; try again. If you call it yourself, check the JSON. |
| `VIT-0009` | The action failed: {0} | An administrator task (`--register-eventlog`, `--apply-config`) failed. Exit code 1. | Run it as administrator; check the message. |
| `VIT-0010` | Unexpected error: {0} | An unexpected error that Vitrine caught; Vitrine keeps running. Written to the audit log as an `Error` entry (`VIT-0010 <exception>`), not shown as a dialog. | If it repeats, report it with the entry (remove names first, see [SUPPORT.md](../SUPPORT.md)). |
| `VIT-0011` | The language could not be saved: {0} | The language choice in the About window could not be written to `%LocalAppData%\Vitrine\preferences.json`. | Check that the profile folder is writable. |
| `VIT-0012` | {0} is ignored: standard users could change or replace it. Save the settings once as an administrator to protect the file. | The device configuration (`%ProgramData%\ICT-Baden\Vitrine\config.json`, or the old `%ProgramData%\Vitrine\config.json`) is not protected: the file, its folder or the folder above is not owned by Administrators, SYSTEM or TrustedInstaller, is a junction or other reparse point, or another account may change, delete, rename or re-permission it. Vitrine ignores the file and uses the other layers. Shown under "Configuration has errors". | Save the settings once as an administrator (directly or through the UAC prompt); this secures folder and file. Typical cause: a file copied by a standard user. Details: [Settings › File locations](settings.md#file-locations). |
| `VIT-0013` | Plugin {0} is not loaded: standard users can change the Plugins folder. Install Vitrine with the MSI. | A plugin DLL, the `Plugins` folder or the folder above it is not protected in the same way as the device configuration (see VIT-0012). The plugin is skipped. Shown under "Plugin not loaded". | Install Vitrine with the MSI (or `install.ps1`) and put the plugin into `%ProgramFiles%\Vitrine\Plugins` – [Plugins](plugins.md). |
| `VIT-0014` | The configuration was not applied: it was changed after the administrator approved it. | The elevated `Vitrine.exe --apply-config <file> --sha256 <hex>` got a file whose SHA-256 does not match (or no checksum). Nothing is written; exit code 1. | Save again in the settings window. `--apply-config` is internal – [Command line](command-line.md#--apply-config-file-internal). |
| `VIT-0015` | {setting}: "{entry}" cannot be read and is ignored. | An entry of a list policy (`Lock.Schedule`, `Appearance.Masks`) or a time in `Lock.Schedule` of a configuration file is not in the expected form, e.g. a schedule with an unknown day (`18:00@Mo-Fx`) or `6:30 PM`. The other entries apply; before 2026-10-20 such entries were dropped silently, and an unknown day meant "every day". | Fix the entry: `HH:mm` or `HH.mm`, days as `Mon,Tue` or `Mon-Fri` ([Settings](settings.md)); areas as `monitor:x,y,width,height`. |
| `VIT-0016` | Unlock.Methods only contains Microsoft Entra ID, which cannot be offered on the lock screen: the Microsoft Edge WebView2 Runtime is missing and the Windows account broker is not used. Unlocking uses the Windows password instead, and Entra.AuthenticationContext does not apply to unlocking. | Warning (since 2026-10-20; since 0.4.0 only when the WebView2 Runtime is missing, VIT-0190). Without Vitrine's sign-in window and without the Windows account broker, the unlock dialog never offers Microsoft. With Microsoft as the only unlock method, Vitrine falls back to the Windows password. Written once per start to the audit log as an `Error` entry (`VIT-0016 Unlock.Methods`), so it appears as a warning in the Windows event log, and shown on the settings overview. | Install the Microsoft Edge WebView2 Runtime, or add `windows` or `hello` to `Unlock.Methods` deliberately – [Entra ID › When Microsoft is not offered for unlocking](entra-id.md#when-microsoft-is-not-offered-for-unlocking). |
| `VIT-0017` | {setting}: the entries {entries} never match a Windows sign-in (Windows reports DOMAIN\name and group SIDs, not UPN suffixes or Microsoft Entra group IDs). The lock screen only offers Windows sign-ins, so nobody may be able to unlock. | Warning (since 2026-10-20). Only Windows password or Windows Hello are left at the lock screen, and `Unlock.AllowedDomains` contains only UPN suffixes (`contoso.com`), or `Unlock.Allowed` allows only groups and `Unlock.AllowedGroups` contains only Entra group IDs. The domain rule is checked before the administrator rule, so with `AllowedDomains` **nobody** can unlock, administrators included. Logged and shown like VIT-0016. | Add the NetBIOS domain (`CONTOSO`) or Windows groups (`CONTOSO\Lab operators`, a SID), or allow the session user or administrators – [Sign-in › Who may unlock](sign-in.md#who-may-unlock). |

## VIT-002x – audit log verification

Shown by **Verify chain** in the settings and by `Vitrine.exe --verify-log <file>` (exit code 2). Details:
[Audit log › Verifying](audit-log.md#verifying).

| Code | Message | Meaning | What to do |
|---|---|---|---|
| `VIT-0020` | Line {0} cannot be read. | The line is not a valid log entry: not JSON, cut off, or `null`. | Compare with the network copy or the event log; find out how the line was damaged. |
| `VIT-0021` | Line {0} (sequence {1}): chain broken – the entry before it is missing or was changed. | `Prev` of this line does not match the line before: a line was removed or changed, or lines were inserted. Also expected where Vitrine started a new chain because the last line could not be read, and in a network copy into which a per-user fallback file also wrote. | Compare with the network copy and the event log. |
| `VIT-0022` | Line {0} (sequence {1}): the content was changed. | The content of this line does not match its own hash. | Treat it as a changed entry; compare with the independent copies. |
| `VIT-0023` | The log file cannot be read: {0} | The file does not exist or cannot be opened. | Check the path and the permissions. |

## VIT-01xx – sign-in and rules

Shown in the unlock, administrator and signature dialogs; each of them counts as a
[failed attempt](sign-in.md#failed-attempts), except VIT-0145. VIT-0150 and VIT-0151 appear in the settings when the
shared unlock password is set.

| Code | Message | Meaning | What to do |
|---|---|---|---|
| `VIT-0100` | Sign-in failed. | General failure: a plugin returned no code of its own, or a sign-in method threw an exception (then with its message). | Check the plugin or the message. |
| `VIT-0101` | The user name or password is incorrect. | Windows error 1326. | Check user name and password; leave the user name empty for the session user. Up to version 0.1.0, Entra accounts on Entra-joined devices always ended here (UPN passed without the domain `AzureAD`); fixed since 0.2.0. |
| `VIT-0102` | The account is restricted or the password has expired. | Windows errors 1327–1330, 1907: account restrictions (logon hours, allowed workstations), password expired or must be changed. | Change the password at the Windows sign-in, or check the account restrictions. |
| `VIT-0103` | The account is disabled. | Windows error 1331. | Ask the account administrator. |
| `VIT-0104` | The account is locked out. | Windows error 1909 – too many wrong passwords in the domain. | Wait for the lockout to end or have the account unlocked. |
| `VIT-0105` | No logon server is available. | Windows error 1311 – no domain controller reachable and no cached logon. | Check the network; use another method (Hello, cached logon of the session user). |
| `VIT-0106` | This account may not sign in on this device. | Windows error 1385 – the account lacks the right to log on locally. | Check the user rights assignment "Allow log on locally" / "Deny log on locally". |
| `VIT-0107` | Please enter the password. | The password field is empty. | Enter the password. |
| `VIT-0108` | For Microsoft Entra ID accounts, enter the sign-in e-mail address (name@contoso.com) as the user name. | In a session of an Entra account, a name without domain or `AzureAD\name` of another person was entered; `AzureAD\name` outside an Entra session; an incomplete name such as `CONTOSO\`. | Enter the UPN, or leave the field empty for the session user. |
| `VIT-0109` | Windows reports: {0} | Any other Windows logon error; the Windows message is shown. | Act on the Windows message. Up to version 0.1.0, `AzureAD\name@contoso.com` ended here with "The network path was not found." (error 53); fixed since 0.2.0 ([Sign-in › Windows password](sign-in.md#windows-password)). |
| `VIT-0110` | Microsoft Entra ID is not set up (application ID missing). | `Entra.ClientId` is empty (only seen in the test sign-in or through a plugin call; the dialog hides the method). | Enter the application ID ([Entra ID](entra-id.md)). |
| `VIT-0111` | Sign-in cancelled. | The Microsoft or Hello window was closed or cancelled. Counts as a failed attempt. | Sign in again. |
| `VIT-0112` | Microsoft Entra ID: {0} | MSAL or Microsoft reported an error; the message often contains an `AADSTS` code. | Look up the `AADSTS` code; check the app registration (redirect URI, public client flows), the network and Conditional Access. |
| `VIT-0113` | This account does not belong to an allowed tenant. | The token's `tid` is not the configured tenant and not in `Entra.AllowedTenants`. | Sign in with an account of your organisation, or add the tenant ID. |
| `VIT-0114` | The sign-in is too old. Please sign in again. | `auth_time` is older than `Entra.MaxAuthAgeSeconds`; usually an existing Microsoft session was reused. | Sign in again; leave `Entra.ForceFreshSignIn` on. |
| `VIT-0115` | The sign-in does not meet the required strength. Please sign in with a method your organisation requires (for example a passkey). | An authentication context is set (`Entra.AuthenticationContext`, `Entra.SignatureAuthenticationContext`) and the ID token reports fulfilled contexts (`acrs`) without it. Entra usually reports `acrs` only in the access token, which Vitrine does not read; then Conditional Access alone enforces the context. | Sign in with a method allowed by the Conditional Access policy for that context; check the policy ([Entra ID](entra-id.md#requiring-passkeys-and-other-strong-methods)). |
| `VIT-0116` | The authentication context "{0}" is not valid (allowed: c1 to c99). The sign-in is refused until the administrator corrects it. | `Entra.AuthenticationContext` or `Entra.SignatureAuthenticationContext` holds something other than `c1` … `c99`. Vitrine refuses the Microsoft sign-in rather than signing in without the required strength; the settings overview shows the same message. | Correct the value (Entra admin centre › Conditional Access › Authentication contexts shows the IDs). |
| `VIT-0117` | Microsoft Entra ID is not restricted to your organization. The administrator must enter the tenant ID (GUID) in Entra.TenantId or Entra.AllowedTenants – otherwise accounts of any organization could sign in. | Since 2026-10-21. Neither `Entra.TenantId` nor `Entra.AllowedTenants` contains a tenant ID (GUID) – for example the default `organizations`, `common` or a domain name. Vitrine refuses every Microsoft sign-in (unlock, e-signature, administrator approval, test sign-in) before the browser opens. Before, any work account of any organization was accepted. | Enter your tenant ID (Microsoft Entra admin center › Overview) in `Entra.TenantId`, or keep `organizations` and list the allowed tenant IDs in `Entra.AllowedTenants` – [Entra ID](entra-id.md). |
| `VIT-0120` | Windows Hello is not available. | Windows Hello could not be started (may be followed by the Windows message). | Check that Hello works at the Windows sign-in; use another method. |
| `VIT-0122` | Too many attempts. | Windows Hello refused after too many failed recognitions. | Use the Hello PIN or another method. |
| `VIT-0123` | Windows Hello is busy. | The Hello device is in use. | Try again. |
| `VIT-0124` | Windows Hello is turned off by policy. | A Windows policy disables Hello. | Use another method, or change the Windows policy. |
| `VIT-0125` | Windows Hello is not set up for this account. | The session user has no Hello sign-in. | Set up Hello in Windows Settings, or use another method. |
| `VIT-0130` | No unlock password has been set. | The method `pin` was used without a stored password. | Set the unlock password, or remove `pin` from the methods. |
| `VIT-0131` | The password is incorrect. | Wrong shared unlock password (or an invalid stored hash). | Enter the right password; if it keeps failing, set it again. |
| `VIT-0140` | {0} may not unlock this workstation. | The sign-in succeeded, but no condition of `Unlock.Allowed` is met. Logged as `UnlockDenied`. | Check the [unlock rules](sign-in.md#who-may-unlock): groups and accounts only count when *Specific groups* / *Specific accounts* is on. |
| `VIT-0141` | Accounts from this domain may not unlock here. | `Unlock.AllowedDomains` is set and the account's domain is not in it, or the account name has no domain. | Add the domain or UPN suffix; plugins must return `DOMAIN\name` or a UPN. |
| `VIT-0142` | Only administrators may do this. | The administrator dialog was confirmed by someone who is not an administrator. | Sign in with an administrator account. |
| `VIT-0143` | This action requires a personal administrator sign-in. | The administrator dialog got a shared secret (e.g. from a plugin). | Sign in personally. |
| `VIT-0144` | A signature requires a personal sign-in. | A shared secret was used in the signature dialog. | Sign in personally. |
| `VIT-0145` | Please wait {0} s. | Waiting time after repeated failed attempts. It applies across dialogs; during it no sign-in is attempted. Not counted as a failed attempt. | Wait, then try again. |
| `VIT-0150` | At least {0} characters. | The new unlock password is shorter than 10 characters. Existing shorter passwords keep working. | Choose a longer password. |
| `VIT-0151` | The two entries do not match. | The two entries of the new unlock password differ. | Enter the same password twice. |
| `VIT-0180` | The Microsoft sign-in cannot be used to unlock: the ID token has no auth_time, so Vitrine cannot tell a real sign-in from one-click single sign-on with the account signed in to Windows. The administrator must add the optional claim auth_time to the ID token of the app registration. | Since 0.4.0. Unlocking or administrator confirmation with Microsoft Entra ID: the ID token has no `auth_time`. Without it, a one-click sign-in through the Windows account broker with the Primary Refresh Token of the account signed in to Windows cannot be told apart from a real sign-in, so Vitrine refuses it. | Add the optional claim `auth_time` (ID token) in the app registration – [Entra ID › App registration](entra-id.md#app-registration). |
| `VIT-0181` | Windows reused an existing Microsoft sign-in instead of asking for your credentials. Unlocking needs a new sign-in – use the Windows sign-in dialog or sign in again. | Since 0.4.0. Unlocking or administrator confirmation with Microsoft Entra ID: `auth_time` is more than 2 minutes before the attempt started – typically the broker signed in silently with the session account's Primary Refresh Token. | Sign in again; use the [Windows sign-in dialog](sign-in.md#windows-sign-in-dialog) (`windowslogon`) for other people on a shared account; check the computer clock. |
| `VIT-0190` | The Microsoft Edge WebView2 Runtime is not installed. Vitrine needs it for its Microsoft sign-in window, so Microsoft Entra ID is not available (and not offered for unlocking). Install the WebView2 Runtime. | Since 0.4.0. Microsoft Entra ID is set up (`Entra.ClientId`), the broker is not used (`Entra.UseBroker = false`, the default, or a build without it), and the WebView2 Runtime is missing (some Windows 10 LTSC images). Vitrine does not fall back to the default browser. Shown on the settings overview, written once per start to the audit log (`VIT-0190 Entra.ClientId`), and returned when a Microsoft sign-in is attempted. | Install the [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) (Evergreen) – [Entra ID › Sign-in window](entra-id.md#sign-in-window). |
| `VIT-0191` | Entra.UseBroker is on: the Windows account broker remembers the accounts that sign in and can sign in with the Windows account of this session without asking. Use it only on devices with one personal user. | Warning since 0.4.0. Shown under the switch, on the settings overview and once per start in the audit log (`VIT-0191 Entra.UseBroker`). Also appears after the update on devices whose `config.json` was saved by the settings window of an earlier version (it contains `"UseBroker": true`, the old default). | On shared devices switch the broker off (`Entra.UseBroker = false`, sign-in window) – [Entra ID › Windows account broker](entra-id.md#windows-account-broker-usebroker--true). |
| `VIT-0192` | The Microsoft sign-in window could not be opened: {0} | Since 0.4.0. WebView2 could not start (for example a damaged runtime, a profile folder that cannot be created under `%LocalAppData%\ICT-Baden\Vitrine\WebView`, or the browser process crashed). Counts as a failed attempt. | Repair or update the WebView2 Runtime; check that the user can write to `%LocalAppData%`. |
| `VIT-0193` | The sign-in page tried to open {0}. Only Microsoft's sign-in pages and the hosts in Entra.AllowedSignInHosts are allowed, so the sign-in was cancelled. | Since 0.4.0. The Microsoft sign-in window opens only HTTPS pages on Microsoft's sign-in hosts (`login.microsoftonline.com`, `login.microsoft.com`, `device.login.microsoftonline.com`, certificate-based sign-in) and on the hosts in `Entra.AllowedSignInHosts`. A link or a redirect to any other address (for example a federation service, *Can't access your account?*, password reset) ends the sign-in, so that nobody can reach a foreign page – and its file or print dialogs – at the locked device. Counts as a failed attempt. | If the host is your federation service or identity provider, add it to `Entra.AllowedSignInHosts` (for example `adfs.contoso.com` or `*.okta.com`) – [Entra ID › Sign-in window](entra-id.md#sign-in-window). Otherwise nothing to do: password reset and registration of sign-in methods are not possible in the sign-in window. |
| `VIT-0194` | The Windows sign-in dialog of the previous attempt is still open and could not be closed. Close it and try again. | Since 0.4.0. With the Windows sign-in dialog (`windowslogon`), Vitrine closes the dialog when the 2-minute limit runs out or the attempt is cancelled, and opens only one at a time. This appears only if the old dialog did not close within 2 seconds. | Close the Windows security dialog, then try again. |

`VIT-0121` is not used.

## VIT-016x – locking Windows

Audit log only (`Error` entries, so they also appear as warnings in the Windows event log); never shown in a dialog.
Background: [Limitations › Win+L](limitations.md#winl-and-other-ways-windows-locks).

| Code | Message | Meaning | What to do |
|---|---|---|---|
| `VIT-0160` | Windows could not be locked: neither locking nor disconnecting the session worked. | A fallback that should lock Windows (watchdog, `FailureAction = LockWorkstation`, elevated window holding the foreground, second instance without hand-over) failed: `LockWorkStation()` did not lock within 3 s and disconnecting the session failed too. The detail names the cause and both Win32 errors. **The session may be open.** | Check the workstation. Check for policies that disable locking and disconnecting (`DisableLockWorkstation`, Remote Desktop Services policies). |
| `VIT-0161` | Windows could not be locked; the session was disconnected instead. | The fallback disconnected the session (Windows shows the sign-in screen, programs keep running): either a policy that Vitrine does not own sets `DisableLockWorkstation` (the detail says `set by HKLM` or `set by HKCU`), or `LockWorkStation()` did not lock within 3 s. Reconnecting needs the Windows password, as after a lock. | Nothing, if expected. To get the normal lock screen, remove `DisableLockWorkstation` from the GPO, or rely on Vitrine, which sets it only while needed. |
| `VIT-0162` | Win+L could not be switched off; it still locks Windows. | Vitrine could not write `DisableLockWorkstation` (or the value that remembers the previous state) under `HKCU`. <kbd>Win</kbd>+<kbd>L</kbd> keeps showing the Windows lock screen – the session stays protected, only less convenient. | Check the permissions of `HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System` and `HKCU\Software\ICT-Baden\Vitrine`. |
| `VIT-0163` | DisableLockWorkstation is set by a computer policy; Vitrine leaves it unchanged. | `HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System\DisableLockWorkstation` exists. With `1`, <kbd>Win</kbd>+<kbd>L</kbd> is already off and fallbacks disconnect the session instead of locking; with `0`, the administrator has allowed locking, and Win+L shows the Windows lock screen during a Vitrine lock. Logged once per start. | Nothing, if intended. |

## VIT-02xx – interface

Error responses of the local [interface](interface.md). They are not translated: the `error` text is always English.
Format: `{"ok":false,"code":"VIT-0203","error":"'reason' is missing"}`.

| Code | `error` | Meaning | What to do |
|---|---|---|---|
| `VIT-0201` | Invalid JSON | The request line is not valid JSON. | Send one JSON object per line, UTF-8. |
| `VIT-0202` | JSON object expected | Valid JSON, but not an object. | Send `{"cmd":"…"}`. |
| `VIT-0203` | 'reason' is missing | `authenticate`/`sign` without a non-empty `reason`. | Always send a reason. |
| `VIT-0204` | Unknown command '{cmd}' | `cmd` is missing or not one of `status`, `lock`, `settings`, `authenticate`, `sign`, `subscribe`. | Check the command name. |
| `VIT-0205` | Interface is disabled | `Integration.PipeEnabled` is off; only `lock` and `settings` work. | Switch the interface on (Settings › Integration & scripts, or policy "Local pipe API"). |
| `VIT-0206` | Cancelled or failed | No signature: the dialog was cancelled or timed out, or another dialog was already open. | Ask the user to try again; check the audit log for `SignatureFailed` entries with their codes. |
| `VIT-0207` | Request longer than 16384 characters | The request line exceeds 16,384 characters; Vitrine closes the connection. | Shorten the request. |
| `VIT-0208` | '{field}' is longer than 500 characters | `reason`, `meaning`, `requester` or `trigger` is longer than 500 characters. | Shorten the field. |
| `VIT-0209` | Workstation is locked | `authenticate` or `sign` while the workstation is locked; no dialog opens. | Ask again after unlocking. |
| `VIT-0210` | – (audit log only) | Another process already owned the pipe name when Vitrine started, so Vitrine does not offer the interface. Written to the audit log as an `Error` entry (`VIT-0210 pipe <name> already exists: …`); clients never receive this code. Text: "Another program already uses the name of the local interface; Vitrine does not offer the interface." | Find and end the other process (it may be trying to impersonate Vitrine), then restart Vitrine. Clients should [verify the server](interface.md#verifying-the-server). |
| `VIT-0211` | Scope '{scope}' is not allowed on this device / 'scopes' must be up to 10 strings without spaces / Access tokens are not allowed on this device / 'scopes' must contain a scope of an API, not only OpenID scopes | `scopes` names a scope that is not in `Entra.AllowedTokenScopes`, or `scopes` is malformed. Since 2026-10-20 also: `Entra.AllowedTokenScopes` is empty (no access tokens at all on this device), or `scopes` contains only OpenID scopes (`openid`, `profile`, `email`, `offline_access`) – those used to return a Microsoft Graph token. | Ask the administrator to allow the scope, or fix the request. For the ID token alone, do not send `scopes`; use `Entra.ShareIdToken`. |
| `VIT-0212` | Scopes of more than one resource | `scopes` mixes scopes of different APIs; one sign-in yields a token for one resource. | Request one resource per call. |
| `VIT-0213` | Tokens need Microsoft Entra ID, which is not set up | `scopes` was sent, but `Entra.ClientId` is empty. | Set up [Entra ID](entra-id.md) or send no `scopes`. |

## VIT-03xx – audit service and signed audit log

Since the service writes and signs the audit log (format 3, [Audit log › Signed audit log](audit-log.md#signed-audit-log-format-3)).
VIT-0301 to VIT-0310 and VIT-0324 are results of **Verify chain** and `--verify-log` (exit code 2); VIT-0300, VIT-0311 to

VIT-0318, VIT-0323 and VIT-0331 to VIT-0333 are written to the audit log as `Error` entries; VIT-0322 is internal
